The window is cut in code, so no validator ever sees more than a reader who stopped would. The contract and the browser cut the same text at the same word, and both are held to the vectors below.

## The cut

The window is the first N whitespace separated words of the title followed by the text, joined by single spaces. Whitespace is whatever Python's `str.split()` splits on, which is every code point for which `str.isspace()` is true: the usual spaces and line breaks, the no-break and ideographic spaces, and a few control characters. A zero width space is not whitespace. Padding with spaces or symbols cannot move the line: it only makes the real text longer.

```python title="contracts/skim.py"
def cut_window(title: str, text: str, words: int) -> str:
    """
    The skim window: the first `words` whitespace separated words of the title
    followed by the text, joined by single spaces. Whitespace is whatever Python's
    str.split() splits on; the site cuts the same text the same way, held to
    tests/vectors.json. The rest is never given to the judge.
    """
    return " ".join((title + " " + text).split()[:words])
```

The same in JavaScript, which is the code the writing box runs for its live skim line:

```js title="web/examples/cut-a-window.mjs"

import { cutWindow, wordCount } from '../lib/cut.mjs';

const title = 'Rewrite the developer docs';
const text = 'We ask for 40,000 USDC to rewrite the docs in Q1, paid in two halves. We need a decision by December 5.';
console.log(cutWindow(title, text, 12));
console.log(wordCount(title, text), 'words in all');
```
